# Deployment and security hardening

Copy `deploy/.env.example` to ignored `deploy/.env`. Replace every placeholder with randomly generated, purpose-separated values; URL-encode the database password inside `RENZAI_DATABASE_URL`. The migration service validates HTTPS public origin, secure cookies, JSON logging, configured database URL, and required secrets before applying migrations. Never pass secrets as Docker build arguments.

Nginx preserves same-origin `/api/` calls, the Gateway compatibility route, health endpoints, request IDs, request buffering, and bounded body/time limits. It overwrites inbound `X-Forwarded-For` with the connecting peer and authors `X-Forwarded-Proto` from its own connection. The operative Uvicorn proxy trust setting is `RENZAI_FORWARDED_ALLOW_IPS` (mapped to `FORWARDED_ALLOW_IPS`), not the parsed `RENZAI_APP_TRUSTED_PROXIES` application setting. Review and narrow the trusted range for the actual Compose network. If TLS terminates ahead of Nginx, adapt the proxy configuration under an explicit trusted-upstream policy so scheme and client IP remain correct; do not simply trust arbitrary forwarded headers. Existing application CSP/security headers remain authoritative for web and API responses.

The baseline is HTTP on loopback. Terminate TLS in an operator-controlled proxy/load balancer or adapt Nginx with operator-managed certificates; do not expose the baseline port publicly while secure cookies expect HTTPS. Review forwarded-header trust whenever network ranges change. Never mount the Docker socket into any Renzai service.
