# Renzai v1.0.0 — Initial Public Release

Renzai v1.0.0 is the initial public source release. The completed local release gate is recorded in
the [Phase 17A review](../phase-17/10-v1-release-candidate-review.md). Container images and SDK
packages are not published to external registries.

Renzai is a self-hostable security control plane for LLM text traffic. Deterministic detectors,
versioned risk and policy, and durable incident evidence remain authoritative; optional AI-generated
incident intelligence is advisory only.

## Highlights

- Eleven documented deterministic threat categories with explainable findings and safe evidence.
- Direct Analyze API and limited, non-streaming, text-only Gateway with fail-closed enforcement.
- Organization-scoped applications, environments, API keys, policy, incidents, and analytics.
- Human-centered dashboard, Security Playground, and analyst workspace.
- Self-hosted Compose stack with migrations, worker, observability, and synthetic demo assets.
- Local typed Python and TypeScript API v1 clients, not yet published to package registries.

## Installation and evaluation

Follow the [Quick Start](../quick-start.md) for the local demo. It prepares a local-only environment,
builds the Compose stack, runs the smoke check, registers `analyst@demo.invalid`, and seeds the
`Renzai Demo Lab` tenant. The demo override is not a production deployment. For a hardened
self-hosted deployment, read the [deployment guide](../phase-15b/10-deployment-and-security-hardening.md).

## Security model

Analysis, risk, and policy decisions are deterministic and versioned. The Gateway inspects input
before a provider call and output before release; inspection failures withhold content. Tenant
boundaries, role checks, session/CSRF controls, encrypted provider credentials, and database
constraints are documented in the [security model](../security/security-model.md). Generated AI
advice cannot enforce policy or change deterministic evidence. Report vulnerabilities privately
through [SECURITY.md](../../SECURITY.md).

## Compatibility and upgrade notes

The verified runtime matrix is in [compatibility](compatibility.md). This is the first public
release; there is no supported upgrade path from older public releases. New installations should
run migrations from an empty database. Existing pre-release operators must back up their data and
validate the documented migration boundary in a disposable environment before changing a live
installation.

## Limitations

The Gateway does not support streaming, tools/functions, multimodal data, or full OpenAI protocol
parity. Detection is bounded and bypassable; the stack is not a SIEM replacement, formal compliance
attestation, external penetration-test certificate, production SLA, or production certification.
Operators own ingress TLS, secrets, backups, network policy, capacity, upgrades, and response.
See the [complete limitations](../limitations.md) and [claims/non-claims](../security/claims-and-non-claims.md).
